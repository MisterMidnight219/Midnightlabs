## Failures, corrections, and technical lessons

The public audit preserves several design corrections and limitations:

- **Recovery classification:** Home Assistant backup policy was corrected from trusting the product's `full` or `partial` type to testing whether the backup actually contains recovery-capable Home Assistant content.
- **Log fidelity:** Home Assistant log forwarding was corrected to preserve source timestamps and remove terminal color escapes.
- **Evidence gap:** The central plane is now reproducible from public artifacts, but several source-side collectors remain private pending separate audit and sanitization.
- **Misleading metric:** The Home Assistant dropped-line counter exists, but the audited code contains no increment path. It must gain real accounting or be removed with its alert.
- **Alert annotation defect:** One recovery alert uses a label name that does not match its metric, which can produce an empty identifier in the description.
- **Authorization uncertainty:** The minimum Home Assistant Supervisor role required for the read-only integration has not been established.
- **Supply-chain consistency:** Some container images are digest-pinned while others use version tags.
- **Notification gap:** Policy evaluation exists, but Alertmanager or another external delivery route is not represented.

These findings remain open rather than being hidden behind the final healthy target count.
